# The light-viewer element

import LiveLightViewer from '@site/src/components/LiveLightViewer';

<LiveLightViewer charts="true" style={{ marginBottom: '1rem' }} />

This is a live `<light-viewer>` showing a track light's IES file. Drag to orbit, scroll to zoom, drag the light to change its height and wall distance, use the gear for viewer settings, and switch tabs for charts. The live demo uses the viewer built with this documentation and may include changes that have not yet been published to npm.

`<light-viewer>` is a web component: it works in plain HTML and in any framework, with no build step.

## Add it to a page

Load the self-contained bundle from jsDelivr, then add the element:

```html
<script type="module" src="https://cdn.jsdelivr.net/npm/@ies-tools/viewer/dist/light-viewer.js"></script>
<light-viewer src="/lights/luminaire.ies" style="height: 600px"></light-viewer>
```

This unversioned URL follows the latest published release, subject to CDN and browser caching. Add an exact version, such as `@ies-tools/viewer@1.2.0`, to pin one.

To self-host, copy `@ies-tools/viewer/dist/light-viewer.js` into your site's public files and point the script at it. With a bundler, install the package and import the element instead:

```sh
npm install @ies-tools/viewer three react react-dom
```

```js
import '@ies-tools/viewer/element';
```

The CDN bundle includes everything it needs. The bundler import uses your copies of `three`, `react` and `react-dom`, and needs no CSS loader.

The element is 480 pixels tall by default; set its height with CSS. Files fetched from another origin must allow it with CORS. Rendering needs hardware WebGL2 and Type C photometry. To check a file first, use [`getPhotometricTypeSupport`](./core.md#sample-intensity).

## Light color

The 3D preview uses one uniform white-light color temperature per luminaire or selected LDT lamp configuration. It reads native LDT color temperature and IES keywords `COLORTEMP`, `CCT`, `COLORTEMPERATURE`, `COLOR_TEMPERATURE`, `TEMPCOLOR` (including underscore-prefixed variants), and `_SEARCH_COLORTEMP`. Explicit fields take priority over descriptions. Without a temperature field, a single unambiguous Kelvin value in the lamp or luminaire description is used.

Missing, invalid, conflicting, or unsupported temperatures default to **6500 K**. The supported range is 1667–25000 K; selectable temperature ranges also use the default. No temperature is inferred from filenames or catalog codes.

The approximate temperature tint is applied in linear RGB before tone mapping and normalized to preserve luminance. Measured candela, calculated lux, and charts remain unchanged. This previews warm/cool white appearance; it does not simulate spectra, CRI, Duv, multiple color channels, or color varying with angle. Tone mapping and exposure affect the displayed color.

## Realistic and measurement views

The buttons beside the gear switch between two views, and between metric and imperial units.

- **Realistic** shows how the light looks on a matte floor (30% reflectance) and a lighter wall (60% reflectance), as a camera would see it. Exposure and tone mapping set the displayed brightness (see [Exposure](#exposure)).
- **Measurement** colors the floor and wall by illuminance and draws isolux lines. The legend lists each line's level in lux, or footcandles in imperial units. The scale runs from the peak illuminance at the current distances down three decades; the colors match the isolux chart. Exposure and tone mapping do not change it.

Imperial units also show the wall and floor distances in feet. The `wall-distance` and `floor-distance` attributes are always metres.

## Exposure

The realistic view is exposed like a camera. **Auto exposure** is on by default: the viewer meters the brightest point on the floor or wall and picks the exposure that keeps it just below white, so the hotspot and its falloff stay visible. It re-meters when you load a file or change the floor or wall distance. Auto exposure changes only overall brightness, never the relative brightness of surfaces, and the glowing fixture uses the same exposure.

The exposure is an EV100 value, the number a camera's light meter reports at ISO 100. Each +1 EV halves the brightness. Typical indoor scenes are about EV 4–8. The settings panel shows the metered EV next to the **Auto exposure** checkbox; clear the checkbox to set your own EV, starting from the metered value. Technically, a surface with luminance 1.2 · 2<sup>EV</sup> cd/m² has the display value 1 before tone mapping.

:::note Behavior change
`exposure` used to be an unscaled brightness multiplier (default `1`). It is now EV100 (default `6`), and auto exposure is on by default. To keep a fixed exposure, set `auto-exposure="false"` and an EV, such as `exposure="6"`.
:::

## Load a file from JavaScript

To show a file the user picked, set its text instead of a URL:

```js
import 'https://cdn.jsdelivr.net/npm/@ies-tools/viewer/dist/light-viewer.js';

const viewer = document.querySelector('light-viewer');
viewer.addEventListener('load', (event) => console.log(event.detail.profile));
viewer.addEventListener('error', (event) => console.error(event.detail.message));
viewer.photometryText = await file.text();
```

Attach listeners before setting a source.

| Property         | What it takes                                                       |
| ---------------- | ------------------------------------------------------------------- |
| `src`            | URL of an `.ies` or `.ldt` file (also an attribute)                 |
| `photometryText` | Raw IES or LDT text; `iesText` and `data` are aliases               |
| `photometry`     | A `PhotometricDocument` from `parsePhotometry` in `@ies-tools/core` |
| `settings`       | Viewer settings; see [Viewer settings](#viewer-settings)            |

| Event            | `event.detail`                                                                                                                           |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `load`           | `{ profile, document, sourceFormat }`                                                                                                    |
| `error`          | `{ message, error }`; the message is also shown unless `errors="silent"`. Bubbles; see [Handle errors yourself](#handle-errors-yourself) |
| `settingschange` | `{ settings, previousSettings }`                                                                                                         |

### Handle errors yourself

The `error` event is a `CustomEvent` (not an `ErrorEvent`) with `detail.message`, a string, and `detail.error`, the original thrown value (usually an `Error`). It bubbles, crosses shadow roots (`composed`), and can't be cancelled, so `preventDefault()` does nothing. The viewer still shows its own overlay unless `errors="silent"`.

Because the event bubbles, it also reaches `error` listeners on `document` and `window`, such as error-reporting tools, which then report a failure you have already handled. Vite's error overlay isn't one of them: it shows only build errors, so a viewer error never opens it. When Vite forwards browser errors to its terminal ([`server.forwardConsole`](https://vite.dev/config/server-options#server-forwardconsole)), an unhandled viewer error is logged there as `[Unhandled error] Unknown Error: [object CustomEvent]`. To keep the error local, call `event.stopPropagation()` in a listener on the element:

```js
viewer.addEventListener('error', (event) => {
  event.stopPropagation();
  showMessage(event.detail.message);
});
```

Listeners on the element itself still run; only listeners further up the page miss the event.

In a React app that renders `<light-viewer>` directly, attach the listener in an effect and remove it on cleanup. This one shows a malformed file's message in the page and rejects a readiness promise, without reaching `window`:

```tsx
import { useEffect, useRef, useState } from 'react';
import type { LightViewerElement } from '@ies-tools/viewer/element';
import '@ies-tools/viewer/element';

declare module 'react' {
  namespace JSX {
    interface IntrinsicElements {
      'light-viewer': React.HTMLAttributes<LightViewerElement> & {
        ref?: React.Ref<LightViewerElement>;
        format?: 'ies' | 'ldt';
        errors?: 'silent';
      };
    }
  }
}

export function Fixture({ text, onReady }: { text: string; onReady: (ready: Promise<void>) => void }) {
  const ref = useRef<LightViewerElement>(null);
  const [message, setMessage] = useState<string>();
  useEffect(() => {
    const viewer = ref.current;
    if (!viewer) return;
    const listeners = new AbortController();
    const { signal } = listeners;
    setMessage(undefined);
    const ready = new Promise<void>((resolve, reject) => {
      viewer.addEventListener('load', () => resolve(), { signal });
      viewer.addEventListener(
        'error',
        (event: Event) => {
          event.stopPropagation(); // keep it away from window listeners
          const { message } = (event as CustomEvent<{ message: string }>).detail;
          setMessage(message);
          reject(new Error(message));
        },
        { signal },
      );
    });
    onReady(ready);
    viewer.photometryText = text;
    return () => listeners.abort();
  }, [text, onReady]);
  return (
    <>
      {message && <p role="alert">{message}</p>}
      <light-viewer ref={ref} format="ies" errors="silent" />
    </>
  );
}
```

The `LightViewer` React component doesn't dispatch DOM events; it reports failures only through `onError`, so it never reaches global handlers.

Changing the source cancels any earlier request. Removing the element stops loading and frees its GPU resources; adding it back recreates the viewer with the same source and settings.

## Wait for rendering and save an image

`whenReady()` resolves once the current source has loaded and its frame is drawn. `toBlob()` waits for the same thing, then renders the current settings and returns an image:

```js
const viewer = document.querySelector('light-viewer');
await viewer.whenReady();
const png = await viewer.toBlob();
const thumbnail = await viewer.toBlob({ type: 'image/webp', quality: 0.85, width: 512, height: 384 });
```

| `toBlob` option   | What it does                                                                |
| ----------------- | --------------------------------------------------------------------------- |
| `type`            | `image/png` (default), `image/jpeg` or `image/webp`                         |
| `quality`         | 0–1 for JPEG and WebP                                                       |
| `width`, `height` | Output size in pixels. Without them the image matches the canvas pixel size |

- The image contains only the 3D scene: the floor, wall, light and any helper lines you've turned on. The illuminance legend, ruler labels, settings panel and chart tabs aren't included. The image is always opaque, with the scene's black background.
- A custom size doesn't change the viewer on the page; the camera keeps the same view at the new aspect ratio. The largest size depends on the GPU; a size it can't allocate rejects with an error.
- If a browser can't encode the format you asked for, it returns a PNG. Check `blob.type`.
- If the source changes before it finishes loading, `whenReady()` waits for the new source.
- Both reject on the same failures as the `error` event (network errors, unreadable files, Type A/B files), if WebGL fails to start or the GPU context is lost, and if the element is removed from the page or was never added. Call them again after a new source or after adding the element back.
- An element without a source resolves immediately and captures the empty scene.

To capture the whole element, legend included, take a browser screenshot once `whenReady()` resolves.

## EULUMDAT files and lamp configurations

```html
<light-viewer src="/lights/luminaire.ldt" format="ldt" lamp-set-index="1"></light-viewer>
```

- `format` forces `ies` or `ldt`. Without it, the format is detected from the content.
- `lamp-set-index` picks one of an LDT file's alternative lamp configurations. It counts from **0**. Files with several configurations need it; single-configuration files don't. It isn't a lamp count or a brightness multiplier.

To choose a configuration in JavaScript, parse the file yourself:

```js
import { parsePhotometry } from '@ies-tools/core';

viewer.photometry = parsePhotometry(ldtText, 'ldt', { lampSetIndex: 1 });
viewer.addEventListener('load', (event) => {
  console.log(event.detail.sourceFormat, event.detail.document.source);
});
```

An invalid format or index fires the `error` event and shows the message.

## Viewer settings

The gear button opens a settings panel. Set the same options with attributes:

```html
<light-viewer
  src="/lights/luminaire.ies"
  settings-panel="open"
  show-wall="true"
  wall-distance="2"
  floor-distance="2"
  tone-mapping="aces"
  auto-exposure="true"
  exposure="6"
  helper="true"
  photometric-solid="false"
  rulers="true"
  view-mode="realistic"
  units="metric"
></light-viewer>
```

| Attribute           | Values                                                                                                                 | Default     |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------- | ----------- |
| `show-wall`         | `true` or `false`: show the back wall                                                                                  | `true`      |
| `wall-distance`     | Distance from the light to the wall, 0.1–100 metres                                                                    | `2`         |
| `floor-distance`    | Height of the light above the floor, 0.1–100 metres                                                                    | `2`         |
| `light-offset`      | Deprecated; will be removed in the next major version. Sideways position along the wall, −100 to 100 metres            | `0`         |
| `tone-mapping`      | `aces`, `agx`, `neutral`, `reinhard`, `cineon`, `linear` or `none`                                                     | `aces`      |
| `auto-exposure`     | `true` or `false`: meter the exposure from the brightest floor or wall point; `exposure` then reports the metered EV   | `true`      |
| `exposure`          | Camera exposure in EV100, −6 to 20; used when `auto-exposure` is `false`. +1 halves the brightness                     | `6`         |
| `helper`            | `true` or `false`: blue lines showing the beam's extent                                                                | `true`      |
| `photometric-solid` | `true` or `false`: amber 3D shape of the candela distribution                                                          | `false`     |
| `rulers`            | `true` or `false`: floor distance rulers and the mounting height                                                       | `true`      |
| `view-mode`         | `realistic` or `measurement`: false-color illuminance with isolux lines                                                | `realistic` |
| `units`             | `metric` (lux, metres) or `imperial` (footcandles, feet) for the legend and panel                                      | `metric`    |
| `settings-panel`    | `closed` (gear shown), `open`, or `hidden` (no buttons or panel, useful for screenshots; the measurement legend stays) | `closed`    |

The helper draws a downward beam's ground circle with four lines to the light. Wider distributions get three axis circles at half the mounting height.

The photometric solid draws the candela distribution around the light: its distance from the light in each direction is proportional to the intensity in that direction, and its peak reaches half the mounting height.

### Moving the light

Click the light to select it; a cyan ring marks it, and the pointer shows a grab hand over it. Drag it to raise or lower it and to move it toward or away from the wall; it never moves sideways along the wall. The wall stays where it is, so height changes set `floor-distance` and moves toward or away from the wall set `wall-distance`. Distances stay within their 0.1–100 metre ranges. With the light selected, Up and Down change its height and Right and Left move it toward and away from the wall (matching the default view, where the wall lies back and to the right), in steps of 0.1 m (0.5 ft in imperial units); Escape or a click on empty space deselects it. Touch screens drag the same way. Each move updates the attributes, the settings panel and a `settingschange` event; the camera stays put. The settings panel's distance fields remain available for exact values.

The rulers run along the floor's two main axes (C0–C180 and C90–C270) through the point directly below the light, with a tick every metre or foot and labels such as `2 m` or `6 ft`, counted from `0` below the light. A vertical ruler on the wall in front of the light shows the mounting height, for example `2.00 m`; with the wall hidden it rises from the floor to the light. Switching units relabels them. The rulers appear in both view modes and in image exports.

The light itself is drawn with the luminous-opening shape from the file (point, rectangle, box, disk, ellipse, cylinder or sphere) at its real size, with a 5 cm minimum so small sources stay visible. Its surface shows the average luminance toward the camera, so a downlight glows when seen from below and shows a dark-grey housing with lighter edges from above. Bright sources usually appear white. Like a camera, the realistic view adds a soft glare around a light that shines toward you, so even small fixtures read at a distance; its strength follows the light's luminance toward the camera and the current exposure, and it is hidden in the measurement view.

Change settings from JavaScript with the `settings` property. It accepts a partial object and returns a copy:

```js
viewer.settings = { showWall: false, floorDistance: 3, toneMapping: 'agx', autoExposure: false, exposure: 7 };
viewer.addEventListener('settingschange', (event) => console.log(event.detail.settings));
```

Settings are kept when you load another file.

## Error overlay

Loading, parsing and initialization failures appear in a translucent overlay at the top-left, above every chart tab. It includes the error message, source and available cause details, a dismiss button, and **Copy to clipboard**. Starting another load clears the previous error.

Omit `errors` to show errors (the default). Set `errors="silent"` to hide the overlay while still receiving the same `error` events:

```html
<light-viewer src="/lights/luminaire.ies" errors="silent"></light-viewer>
```

Changing `errors` takes effect immediately without reloading. Removing it reveals the current error unless it was dismissed or cleared.

## Chart tabs

Add `charts="true"` to show a tab bar: the 3D view, then **Polar**, **Cartesian**, **Topology**, **Isolux**, **Cone**, **Luminance** and **Intensity table**. The Polar and Cartesian tabs have a **Log scale** checkbox, and the Isolux tab uses the floor distance as the mounting height. The settings panel applies to the 3D view only. See [Charts](./graphs.md) for how to read each chart.

```html
<light-viewer src="/lights/luminaire.ies" charts="true"></light-viewer>
```

## Match your site's colours

The controls take their colours from `--ies-viewer-*` CSS custom properties such as `--ies-viewer-popover`, `--ies-viewer-foreground` and `--ies-viewer-border`, set on the element or an ancestor. Without them it uses a dark theme. Generic page variables such as `--foreground` are ignored. The 3D scene's background is always black. See [Styling and themes](./styling.md).

## Use the viewer without the element

`createLightViewer` puts the same 3D viewer in any container, without the web component:

```js
import { createLightViewer } from '@ies-tools/viewer';

const viewer = createLightViewer(document.querySelector('#viewport'), { height: 2 });
viewer.load(iesOrLdtText);
viewer.setExposure(7); // manual EV100; turns auto exposure off
// When you remove the view:
viewer.dispose();
```

`height` is the light's height above the floor in metres; size the container with CSS.

- `load(text, format?, { lampSetIndex? })` loads IES or LDT text and returns the profile. `loadDocument` takes the same arguments and returns the full `PhotometricDocument`.
- `setProfile(profile)` and `setDocument(document)` show data you've already parsed.
- `getSettings()`, `setSettings(patch)` and `settingschange` listeners work like the element's `settings`.
- `capture(options?)` returns a `Promise<Blob>` of the current scene, with the same options as the element's `toBlob()`.
- `renderer` is the underlying Three.js `WebGLRenderer`.
